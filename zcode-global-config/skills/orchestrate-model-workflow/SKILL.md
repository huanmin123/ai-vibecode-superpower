# 多模型工作流编排

本 Skill 规定复杂任务的协作行为。ZCode 原生负责子代理的创建、上下文传递、通信、等待、中断和汇总（Agent 工具）；主代理负责核验真实状态、diff、产物和验证结果。

## 适用范围

简单问答、只读查询和边界清晰的单文件低风险整理由主代理直接完成并验证。跨文件、未知根因、需要独立复审、共享状态或高回归风险的任务按以下阶段推进：

`Explore -> Plan -> Work -> Critique -> Promote`

这些是行为阶段，不是固定的运行时节点或工具顺序。

默认并行优先：任务可拆成两个以上边界清晰、互不依赖且产出明确的子任务时，主代理应使用多个子代理同时处理，不应只交给单个子代理串行执行。无法安全拆分、拆分成本高于收益或当前工具受限时，才使用单代理。

## 协作边界

- 委派前明确目标、范围、权限、验收、验证、停止条件，以及执行和集成责任；未决选择不得交给执行者自行补全。
- 子代理只能修改分配范围，不得覆盖或回滚其他改动；共享文件、数据和外部状态按必要顺序处理。
- 子代理只向直接委派它的父任务汇报。不得根据任务路径、历史会话 ID 或上下文中的旧 ID 自行选择会话；无法确认父任务时，只在自身最终消息返回，不跨会话发送。跨会话通信必须由主代理明确授权。
- 主代理只采纳当前直接子代理的结果；其他会话的消息视为外部信息，不自动合并。

## 角色选择

角色定义的权威来源是 `<ZCODE_HOME>/agents/ai-vibecode-superpower/`（name、description、model、thoughtLevel、tools）。角色经 Agent 工具的 `subagent_type` 按名称派发。

角色命名格式为 `模型_版本_类型_思考档`（如 `glm_5.3_flash_low`），名称本身标明模型与档位；该格式跨客户端统一，未来移植到其他客户端时沿用同一公式，只替换模型与档位取值。

- `glm_5.3_flash_low`：常规跨文件取证、扫描和预审，只读。
- `glm_5.3_flash_high`：需要更深局部理解的取证和复杂预审，只读。
- `glm_5.3_flash_max`：写代码主力——受控契约执行、受保护写入、共享状态处理、执行监管和集成。
- `glm_5.3_high`：证据充分、范围有界的定案或常规复审，只读（审核主力）。
- `glm_5.3_max`：最高强度独立复审与最终升级验收，只读（终审）。

档位分配按 GLM 自身语义定义，不与 Codex 对齐。GLM-5.3-Flash 使用全部三档：low=常规取证，high=深度取证，max=写代码。GLM-5.3 只用 high 和 max，且只用于审核：high=审核主力，max=终审；不使用 low 档。风险、权限、上下文和验收条件相当时，取证优先选择较低成本档位，写入统一使用 `glm_5.3_flash_max`，复审从 `glm_5.3_high` 起步，最高强度或最终升级验收使用 `glm_5.3_max`。role 的 `tools` 白名单和 `thoughtLevel` 是配置意图，不单独证明硬隔离或推理深度。每次派发前核验当前宿主权限和角色可用性；只有本次明确确认不可用时，才为本次操作选择职责、权限和验收能力等价的 fallback，并保留原始错误和发生时点。无法证明等价时停止并报告。fallback 仅对本次派发生效，是临时且可重新评估的选择；重试、进入下一阶段或再次需要该角色时必须重新探测，恢复后优先回到原始角色。普通超时、证据不足或执行失败不应被静默降级。

## 阶段要求

### Explore

检查相关代码、配置、文档、测试、调用关系和当前 diff；把互补且只读的独立证据域优先交给多个取证角色（`glm_5.3_flash_low`，需要更深理解时用 `glm_5.3_flash_high`）并行取证。输出事实、来源、推断、未知项、风险和下一步，不把线索直接定性为缺陷。

### Plan

主代理基于证据明确目标、范围、非目标、授权、验收、验证和停止条件。多个子代理写入时，只划分完成任务所需的最小范围，优先按功能、模块或文件形成非重叠区域；共享部分按必要顺序处理，不因局部冲突取消其他可安全并行的工作。未决选择、权限、依赖或环境问题不得交给执行者自行补全。

### Work

按已定契约实施。写入统一交给 `glm_5.3_flash_max`；不可逆变更、外部副作用、共享状态或风险未受控时，主代理先补齐授权、回滚和验收边界再派发。每个子代理只能修改事先分配的最小范围，不得覆盖其他子代理；边界清晰的工作保持并行。执行者返回实际改动、验证结果、原始错误、影响范围和未完成项；主代理集成前核对状态和 diff，不把自述当作完成证明。

### Critique

完成实施及相关验证后，由未参与写入的只读角色独立核对目标、范围、diff/产物、测试、回归、需求覆盖和未验证项。常规定案或常规复审可用 `glm_5.3_high`；最高强度或最终升级验收使用 `glm_5.3_max`。发现 blocker 时回到 Plan/Work 精确修复，再选择新的独立复审者；不得把失败包装为通过。

### Promote

只有验收满足、独立复审无 blocker、当前 diff 与验证仍匹配且没有必需工作时才交付。Promote 不授权安装、发布、部署、推送或其他外部状态变更。

## 错误与恢复

保留原始 provider/宿主错误、已尝试操作、影响范围和缺失条件。子代理因权限不足、缺少授权、目标超出边界或责任冲突而拒绝时，结束该次委派，保留原始拒绝，不再等待该子代理或原样重复派发。先补齐授权、收缩范围、消除责任冲突或选择匹配的角色；拒绝条件已经改变时可以重新派发，并说明前次拒绝。拒绝不等于角色不可用，不触发 fallback。不得把写入任务派给只读角色。主代理仅在授权、权限、范围和责任边界均已满足时直接继续，否则向用户说明阻塞。中断后重新盘点子代理状态、工作区 diff 和输出；无法证明旧执行者已停止时，不得接管其范围。风险、授权或范围改变时回到 Plan，不得静默扩大。
