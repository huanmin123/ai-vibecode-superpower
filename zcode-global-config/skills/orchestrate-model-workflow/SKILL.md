# 多模型工作流编排

ZCode 负责子代理的创建、上下文传递、通信、等待、中断和汇总；主代理负责契约、集成和验收。

## 适用范围

简单问答、只读查询和边界清晰的单文件低风险整理由主代理直接完成。跨文件、未知根因、需要独立复审、共享状态或高回归风险的任务按 `Explore -> Plan -> Work -> Critique -> Promote` 推进。

默认并行优先：任务可拆成两个以上边界清晰、互不依赖且产出明确的子任务时，主代理应使用多个子代理同时处理，不应只交给单个子代理串行执行。无法安全拆分、拆分成本高于收益或当前工具受限时，才使用单代理。

## 协作边界

- 子代理只修改分配范围，不得覆盖或回滚其他改动；共享文件、数据和外部状态按必要顺序处理。
- 子代理只向直接委派它的父任务汇报；无法确认父任务时只在自身最终消息返回。跨会话通信必须由主代理明确授权。
- 主代理只采纳当前直接子代理的结果，其他会话的消息视为外部信息。

## 角色选择

角色定义的权威来源是 `<ZCODE_HOME>/agents/` 顶层平铺的 5 个 md 文件（名称、描述、模型、思考档位、工具范围）；宿主只扫描该层，子目录不参与发现。角色按名称派发给对应的子代理角色定义。

角色命名格式为 `模型_版本_类型_思考档`（如 `glm_5.3_flash_low`），名称本身标明模型与档位；该格式跨客户端统一，未来移植到其他客户端时沿用同一公式，只替换模型与档位取值。

- `glm_5.3_flash_low`：常规跨文件取证、扫描和预审，只读。
- `glm_5.3_flash_high`：需要更深局部理解的取证和复杂预审，只读。
- `glm_5.3_flash_max`：写代码主力——受控契约执行、受保护写入、共享状态处理、执行监管和集成。
- `glm_5.3_high`：证据充分、范围有界的定案或常规复审，只读（审核主力）。
- `glm_5.3_max`：最高强度独立复审与最终升级验收，只读（终审）。

默认优先选择成本最低且能胜任的取证角色；需要写入、独立复审或更高强度时，再用 `glm_5.3_flash_max`、`glm_5.3_high` 或 `glm_5.3_max`。角色配置只表达意图，不单独证明隔离效果。

## 阶段要求

### Explore

检查相关代码、配置、文档、测试、调用关系和当前 diff；互补且只读的独立证据域交给多个取证角色并行取证。输出事实、来源、推断、未知项、风险和下一步，不把线索直接定性为缺陷。

### Plan

主代理基于证据明确目标、范围、非目标、授权、风险与回滚、验收、验证、停止条件，并划分写入的最小非重叠范围；共享部分按必要顺序处理，不因局部冲突取消其他可安全并行的工作。未决选择、权限、依赖或环境问题由主代理解决，不交给执行者补全。

### Work

按 Plan 的契约实施。写入统一交给 `glm_5.3_flash_max`；不可逆变更、外部副作用、共享状态或风险未受控时，主代理先补齐授权、回滚和验收边界再派发。执行者返回实际改动、验证结果、原始错误、影响范围和未完成项；主代理核对状态和 diff 后再集成，不把自述当作完成证明。

### Critique

由未参与写入的只读角色独立核对目标、范围、diff/产物、测试、回归、需求覆盖和未验证项。常规定案或常规复审可用 `glm_5.3_high`；最高强度或最终升级验收使用 `glm_5.3_max`。发现 blocker 时回到 Plan/Work 修复，再选择新的独立复审者；不得把失败包装为通过。

### Promote

验收满足、独立复审无 blocker、当前 diff 与验证仍匹配且没有必需工作时才交付。Promote 不授权安装、发布、部署、推送或其他外部状态变更。

## 错误与恢复

保留原始 provider/宿主错误、已尝试操作、影响范围和缺失条件。

子代理因权限、授权、范围或责任冲突拒绝时，结束该次委派并保留原始拒绝；补齐条件或选择匹配角色后再派发，并说明前次拒绝。拒绝不等于角色或模型不可用，不触发 fallback。不得把写入任务派给只读角色。拒绝场景下，主代理仅在授权、权限、范围和责任边界均已满足时直接继续，否则向用户说明阻塞。

角色或模型不可用时，先换职责等价的可用角色；仍不可用则派发一个继承当前会话模型的子代理，承担原角色职责，其余流程不变，主代理不得改为在当前会话内直接执行。fallback 只对本次派发生效，恢复后回到原角色；普通超时或执行失败不静默降级。

中断后重新盘点子代理状态、工作区 diff 和输出；无法证明旧执行者已停止时，不得接管其范围。风险、授权或范围改变时回到 Plan，不得静默扩大。
