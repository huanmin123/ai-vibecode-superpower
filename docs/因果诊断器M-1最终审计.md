# 因果诊断器 M-1 最终审计

> 审计日期：2026-08-28  
> 当前决定：**No-Go**。M-1 runner、证据包审计、只读第一版插件和真实 A/B 流程可运行，但正式 Gate 前置条件未满足，因此不放行生产级完整能力。

## 结论先行

本轮已经证明的是“验证基础设施可用、窄证据包在部分局部故障上能帮助模型更快收敛”，没有证明“因果诊断插件可以在一般模糊问题上稳定定位根因”。正式门禁不能放行，原因是样本规模、重复、回归和完整性仍不足，且多次 baseline 超时或超 token；cross-service Spike 还出现过高置信错误。

## 关键真实信号

- `CLIProxyAPI` tool-search-template：assisted `59,925 ms`、input `86,759`、Top-1 命中；baseline `180,000 ms` 超时。该样本只说明窄 packet 有方向性收益，不能计算完整 token 降幅。
- `CLIProxyAPI` WebSocket `1009`：两臂 Top-1 命中，assisted 时间和 input 明显较低，但严格关系身份不一致；这直接促成 `relationId` 契约加固。
- `CLIProxyAPI` XAI compact 与 `sub2api-lite`/Java 等样本中，局部问题常能由 packet 快速收敛；cross-service 样本出现高置信错误，说明不能把静态图当作运行时因果证据。

## 后续放行条件

只有在新的未揭示候选完成冻结、每条关系预分配 `relationId`，并组成同一 `mode=gate` suite，满足 ≥20 Bug、≥3 仓库、6 类、≥3 重复、至少一个 fixed regression，且所有 run 具备 provider usage、候选时间线和原始 transcript 后，才允许重新执行 evaluator。任何一项失败都继续输出 `insufficient_data` 或 `no_go`，不进入完整插件实现。
