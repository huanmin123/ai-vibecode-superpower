# 项目文档

## 目录定位

`docs/` 保存可提交的稳定设计、边界、验收标准和维护说明。真实开发、测试、生产环境事实、凭据、日志和发布产物不放在这里；如后续确有需要，使用被 Git 忽略的 `.local/project-resources/` 保存私有事实。

## 适用范围

- 设计或实现因果诊断插件前，先阅读 [`因果诊断器设计.md`](因果诊断器设计.md)。
- 修改插件的图模型、证据来源、评分、MCP 工具或 Skill 流程时，必须同步该设计文档。
- 现有多代理工作流、角色路由和安装行为继续以根目录 `AGENTS.md`、`plugins/agnets-workflow/` 和安装脚本为准；本目录不复制这些细节。

## 新增规则

- 稳定架构和接口约束放在本目录；一次性实施拆分、进度和执行记录放在 `plans/`，只有确有持续维护价值时才新增该目录。
- 文档默认使用简体中文；代码、命令、路径、配置键、协议字段和插件标识保留原文。
- 不把设想中的功能写成已实现事实。状态、待确认项和验证证据必须明确区分。
- 不在公开文档中写入真实凭据、主机地址、连接串、生产日志或其他私有环境事实。

## 维护规则

- 插件目录、MCP 工具或 Skill 发生结构变化时，更新设计文档中的架构图、接口表和文件布局。
- 图模型、评分公式或证据等级变化时，更新数据模型、分析流程、风险与验收标准。
- 完成一个实现阶段后，把文档状态改为当前实现状态，并补充实际验证命令和结果；未验证内容不得标记为完成。

## 推荐阅读顺序

1. 先读 [`因果诊断器真实项目可行性验证.md`](因果诊断器真实项目可行性验证.md)，确认当前 Go/No-Go 状态和未证明项。
2. 再读 [`因果诊断器设计.md`](因果诊断器设计.md) 的“结论与范围”“核心模型”和“分析流程”。
3. 需要核对 CodeGraph 能力边界时，阅读 [`CodeGraph验收测试报告.md`](CodeGraph验收测试报告.md)。
4. 实现 MCP 或 Skill 前，按设计中的阶段门、接口契约、权限边界和验收标准逐项核对。
