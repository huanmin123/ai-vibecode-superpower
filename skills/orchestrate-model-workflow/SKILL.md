# 多模型工作流编排

本 Skill 提供行为级工作流指导。Codex 原生负责创建 agent、传递上下文、通信、等待、中断和汇总；main/root 必须核验真实状态、diff、产物和验证输出。

## 何时使用

简单问答、只读查询或单文件且边界清晰的低风险整理由 main/root 直接完成，并运行贴近改动的验证。跨文件、未知根因、需要独立复审、共享状态或高回归风险的任务使用以下主线：

`Explore -> Plan -> Work -> Critique -> Promote`

这些名称是进度语言，不是运行时节点或固定工具调用顺序。

## 角色选择

- `avsp_luna_high`：常规跨文件取证、扫描和预审，只读。
- `avsp_luna_xhigh`：需要更深局部理解的取证和复杂预审，只读。
- `avsp_luna_high_executor`：目标、授权、范围、验收和停止条件已明确时的受控写入。
- `avsp_luna_xhigh_executor`：已定方案但需要更深局部理解的受控写入。
- `avsp_terra_high`：受保护写入、共享状态、风险分流、执行监管和集成。
- `avsp_terra_xhigh`：证据充分、范围有界的定案或常规复审，只读。
- `avsp_sol_high`：多约束、跨域或高复杂度的独立复审，只读。
- `avsp_sol_xhigh`：证据冲突、根因未证实、缺少可靠 oracle 或需受约束重设计，只读。
- `avsp_sol_max`：前级 Sol 有效失败修复后的最高强度独立复审，只读。

在风险、权限、上下文和验收条件相当且角色可用时，默认优先选择 Luna；只有保护执行、复杂度或独立性要求确实需要时才选择 Terra 或 Sol。role 的 `sandbox_mode` 是配置意图，不单独证明硬隔离；父 agent 必须在每次派发前核验当前宿主的真实权限和模型可用性。只有本次派发明确确认 role/model 不可用时，才为本次操作选择对应 fallback，并保留原始错误和发生时点。fallback 是局部、临时且可重新评估的选择，不构成当前会话或后续阶段的永久禁用；重试、进入下一阶段或再次需要该 role 时必须重新探测，恢复后优先回到 Luna。普通超时、证据不足或执行失败不应被静默降级。

## Explore

检查相关代码、配置、文档、测试、调用关系和当前 diff。可把互补且确实只读的证据域交给 Luna 并行取证。返回事实、来源、推断、未知项、风险和下一步，不把线索直接定性为缺陷。

## Plan

main/root 根据证据写清目标、范围、非目标、授权、验收、验证和停止条件。需要多个 agent 写入时，main/root 只划分完成任务所必需的最小范围，优先按功能、模块或文件形成互不重叠的负责区域；只有确实存在独立边界时才并发，重叠部分按必要顺序处理，不因并发风险擅自扩大范围或取消其他可安全并行的工作。未决选择、权限或兼容性问题不得交给 executor 自行补全。

## Work

按已定契约实施。影响受控、可恢复且验证可靠的写入可交给 Luna executor；共享状态、不可逆变更、外部副作用或风险未受控的写入由 Terra 保护执行。多个 agent 并发写入时，只能修改事先分配的最小功能、模块或文件范围，不得覆盖其他 agent 的负责范围；互不相关且边界清晰的工作应保持可并行。执行者必须返回实际改动、验证结果、原始错误、影响范围和未完成项。父 agent 在集成前重新核对状态和 diff，不把自述当作完成证明。

## Critique

完成所有会改变被审对象的验证后，由未参与写入的只读 role 独立核对原始目标、范围、diff/产物、测试、回归、需求覆盖和未验证项。常规定案可用 Terra/xhigh；复杂或高不确定性使用 Sol。发现 blocker 时回到 Plan/Work 精确修复，再选择新的独立复审者；不得把普通失败包装为通过。

## Promote

只有验收满足、独立复审无 blocker、当前 diff 与验证仍匹配且没有必需工作时才交付。Promote 不授权安装、发布、部署、推送或其他外部状态变更。

## 错误、恢复和并发

保留原始 provider/宿主错误、已尝试操作、影响范围和缺失条件。中断后先重新盘点原生 agent 状态、工作区 diff 和输出，无法证明旧执行者已停止时不得接管同一范围。多 agent 写入由 main/root 预先安排最小且非重叠的功能、模块或文件范围；仅对确实共享的文件、数据或外部状态按依赖顺序处理，其他边界清晰的工作继续并行，避免相互覆盖。风险、授权或范围改变时回到 Plan，不得静默扩大。
