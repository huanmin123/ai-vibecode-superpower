# 性能测试（performance）

性能测试回答“够不够快、够不够稳”，不验证功能正确性。它与功能基线、场景测试是三条独立轨道，不进入 5 分钟功能反馈循环。

## 触发前提

- 项目有明确 SLO/性能目标；或
- profile、复杂度分析、线上指标证明改动影响热点。

仅“涉及缓存/序列化/启动”等宽泛关键词不构成运行理由；不运行时在交付证据中写明原因。

## 子类型

| 类型 | 目的 | 典型时长 | 环境 | 默认运行 |
| --- | --- | --- | --- | --- |
| 微基准（microbenchmark） | 函数、热点路径、数据结构的相对性能 | 秒级 | 固定机器/容器，release 构建 | 改动热点时按需 |
| 负载（load） | 目标 SLO 下的吞吐、延迟、错误率 | 分钟级 | 专用测试环境 | 发布前/按需 |
| 压力（stress） | 找到饱和点、限流点和失效模式 | 分钟级 | 专用测试环境 | 容量评估/按需 |
| 浸泡（soak） | 长时间稳定性、内存/连接泄漏 | 小时级 | 专用测试环境 | 夜间/发布前 |

## 先定目标和环境

跑之前写清楚：

- **假设**：这次改动预期影响哪个指标，为什么。
- **指标**：p50/p95/p99 延迟、吞吐、错误率、CPU、内存、GC、分配次数、启动时间等，选与目标相关的。
- **工作负载**：数据规模、并发数、请求/操作组合、思考时间、持续时间；不要只测单条最快路径。
- **环境**：同一台机器或同一容器规格、相同依赖版本、相同数据集、release 构建；关闭后台负载和共享 CI 噪声；记录 runner 类型。
- **阈值**：通过/失败标准和允许的噪声范围，必须在看到结果前确定。

## 测量规则

- 先 warm-up，再正式采样；微基准至少多轮重复，报告中位数和离散度。
- 报告 p95/p99 和错误率，不只报平均值；负载下“快速失败”不是高性能。
- 区分两种对比：
  - **重复性测量**：同 commit、同环境、同数据、同构建，用于确认结果稳定。
  - **A/B 对比**：对照版本/候选版本两个 commit，必须同机器、同数据、同 release 构建，交替或随机顺序运行，记录两个 commit 和依赖，用置信区间或约定容差判断。跨机器、跨数据集的结果只作参考。
- 一次只改一个变量；优化前先 profile，不凭直觉改热点。
- 记录元数据：commit、构建模式、依赖版本、机器/容器规格、数据集、并发、运行时长、runner 类型。
- 保存结果并维护基线；只有稳定、专用 runner 才允许硬失败；共享 runner 只记录趋势和告警，不阻塞 PR。
- 微基准用统计方法判断差异（如多次采样、置信区间）；单次跑分不得作为结论。

## 数据生命周期

- 使用合成数据或已脱敏数据；禁止生产数据和共享开发数据。
- 每次运行使用唯一命名空间；结束删除数据集、容器和临时资源；失败时也清理并记录结果。
- 记录数据规模、生成方式和清理结果，保证可重复。

## CI 与门禁

- 功能基线：每个 PR，按模块，≤5 分钟。
- 微基准：稳定 runner 上按需/夜间；共享 runner 上的微基准只做趋势，不做硬门禁。
- 负载/压力/浸泡：独立 job，夜间、发布前或手动触发；不要放在每个 PR 的默认流水线。
- 性能门禁只对稳定、可复现的指标设置；噪声大的指标先观测趋势，不急着卡阈值。

## 工具示例

按项目生态选择，命令以项目脚本为准：

- JS/TS：`vitest bench`、`tinybench`；HTTP 用 `k6`、`autocannon`。
- Python：`pytest-benchmark`、`pyperf`；负载用 `locust`。
- Go：`go test -run '^$' -bench . -benchmem -count=10 ./<pkg>`，对比用 `benchstat old.txt new.txt`。
- Rust：`cargo bench`（criterion）。
- JVM：`JMH`。
- .NET：`BenchmarkDotNet`。
- HTTP 压测：`k6`、`hey`、`wrk`、`vegeta`、`Artillery`。
- 浏览器：Lighthouse、Playwright trace（注意观测开销）。

## 反模式

- debug/未优化构建上跑分。
- 只跑一次、只看平均值、没有 warm-up。
- 在不同机器或不同数据集上直接比较，或把共享 runner 的噪声当回归。
- 没有 profile 就改代码“优化”。
- 负载测试不记录错误率和饱和点。
- 用性能测试替代功能测试，或把性能用例塞进 5 分钟功能基线。
- 忽略 GC、内存、连接数和尾延迟。
- 没有 SLO 或热点证据就为普通改动跑性能测试。
