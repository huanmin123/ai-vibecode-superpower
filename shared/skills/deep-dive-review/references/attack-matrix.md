# 攻击矩阵

把锚定范围展开成显式矩阵，让"穷举"变成可度量的覆盖。相邻轮视角互不相同，防止同一批攻击面重复扫描产生"假干净"。

## 基础视角（前三轮骨架）

### 维度制（首轮适用）

对锚定范围内的代码逐维度展开，每个维度即矩阵的一行：

1. **状态一致性**——所有可变状态的不变量、转换合法性、并发可见性。
2. **并发与时序**——竞态、交错、重入、异步完成顺序。
3. **取消与中断**——中途取消、超时、部分失败后留下的状态。
4. **错误路径与边界**——每个 throw/拒绝/空值/越界/极值的下游走向。
5. **资源与生命周期**——泄漏、重复释放、初始化顺序、关闭顺序。
6. **数据流与契约一致**——文档/接口声明与实际行为逐条对照。
7. **外部输入**——注入、编码、大小上限、频控、恶意构造。
8. **回归与兼容**——本变更对既有调用方和既有行为的影响。
9. **性能与放大**——热路径、批量、嵌套循环、无界增长。
10. **测试有效性**——测试是否真钉住行为（断言强度、覆盖的路径）。

### 场景制（第二轮适用）

入口 × 输入空间 × 时序：列出对象全部入口（API、命令、事件、用户操作），每个入口展开：

- 输入空间：典型值、空值、极值、非法值、并发重复值。
- 时序：首调、重入、并发、取消、重试、失败后再次进入。

上一轮扫过的场景本轮不复用结论，重新取证。

### 交互制（第三轮适用）

模块对 × 共享状态 × 事件交错：从锚定范围内取有实际耦合的模块对（共享可变状态、事件订阅、调用依赖），对每对枚举交错时序——A 写 B 读、A 失败 B 继续、A 取消 B 挂起、A/B 同时写同一状态等。另做**修复间交互审查**：同文件多批修复逐对排查（修复 A 是否破坏或削弱修复 B）。

## 扩展视角池（第四轮起按锚定对象特征选用）

实战沉淀的六个扩展视角，各抓一类基础视角照不到的缺陷；按对象特征选用、按需继续扩充（新视角按同格式沉淀回本清单）：

- **数据演化×边界态**——空库冷启动全路径、存量数据与新代码假设的错配、单条/满尺寸/规模形态、时间时区边界、字符编码边界。抓"新代码对数据形态的假设"缺陷。
- **消费者契约×外部视角**——响应形状横向一致（分页/时间戳/ID 类型/null 语义）、错误码穷举与 HTTP 语义、文档↔后端↔前端类型三方逐字段对照、外部可见变化登记完备性。抓"文档系统性落后实现"与跨端点不一致。
- **运维与部署面**——必填配置矩阵与静默降级、健康检查语义、发布/回滚/迁移/启动顺序、观测与日志、容量弹性、共享资源竞争。抓"故障静默不可见"。
- **数据全生命周期×备份恢复**——恢复演练路径、升级链从零跑通、数据老化与清理、修复在备份/重放/升级场景的活性。适合复核轮。
- **操作序列×降级组合**——长操作序列链（第 N 步才触发的状态残留）、依赖降级组合矩阵（每依赖宕/慢/恢复 × 各功能）、重复/回退/重放序列。抓"单步正确、序列漂移"。
- **前端本地状态×身份生命周期**——本地存储键清单与容错、会话恢复状态机、token 过期/刷新/多标签、路由守卫重估、身份时点变化（降权/停用/改名）。抓前端长会话缺陷。

视角选择依据：锚定对象特征（纯后端服务跳过前端视角；有持久化状态必选数据演化；对外 API 必选消费者契约）+ 台账已用视角记录。

## 格子填写要求

矩阵每格只接受两种写法，缺一视为未覆盖：

- `已查 | 未发现 | 理由`——理由写具体依据（读了哪些路径、为什么不成立），不接受"没发现问题"。
- `发现 → 台账编号`——产出假设进台账条目表。

大型锚定对象（矩阵 > 30 格或跨多域）允许以"复核通过面"文字结论代替逐格矩阵，但每条结论必须带 file:line 依据。

## 扩散规则

每轮结束按耦合强度取下一跳，只扩一跳：

1. 共享可变状态
2. 共享文件
3. 事件订阅 / 调用依赖
4. 主题相似（最后手段，必须说明具体共同点）

新对象登记进台账扩散记录（对象、耦合类型、纳入理由）后进入下一轮 1-4 阶段。排除项同样登记（如并行会话正在修改的域、明确不纳入的接缝）。

## 视角登记

每轮开工时在台账登记视角类型。收敛终止要求最近三轮视角互不相同；视角不足以轮换时，收敛终止的视角条件不满足，相应轮次不得计入干净轮。
