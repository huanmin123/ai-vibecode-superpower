# 攻击角色派发提示词（attacker brief）

攻击轮的假设质量由派发提示词决定。泛泛的"找一下问题"产出表象清单；按本骨架定制的攻击点清单才产出可验证的深水区假设。验证者模板见 [verifier-protocol.md](verifier-protocol.md)，两者配对使用。

## 派发提示词固定骨架

按序七段，缺一段质量即降级：

1. **角色与约束**：明确"只读，禁止修改任何文件"（攻击轮）；收敛复核轮改为"只读；优先尝试证伪已修复行为，只报告前几轮未覆盖且真实成立的新缺陷——零新发现是本轮的成功结果"。
2. **业务脉络摘要**：从台账复制压缩——对象一句话、关键契约（逐条）、项目裁决（影响本面的）、已知问题史（作为回归先验）。≤15 行。
3. **聚焦范围**：明确的文件/目录清单（带角色分工），范围外明确排除（含并行会话正在修改的域）。
4. **攻击点清单**：主代理预先定制的 5-10 个具体攻击方向，每条带"证伪点"提示（该方向上最容易误判的是什么）。这不是装饰——攻击点清单的质量直接决定假设质量，禁止用泛化指令代替。
5. **模式声明**：攻击轮用"宁滥勿缺，可疑即报，不要求证据完备，不得自我过滤"；收敛轮用"通过项逐条列结论，通过是本轮的成功结果"。
6. **输出格式**：`H<n>｜维度/场景/交互对｜假设一句话｜触发条件（具体输入/时序）｜疑似后果｜初判依据 file:line`；每条必须有真实 file:line，纯猜测标注（猜测）；末尾覆盖结论一行（已查清单/未发现+理由/发现→编号）；全输出设行数上限（45-70 行）。
7. **排除声明**：前几轮已裁决接受项、已证伪项、明确排除的域——逐条点名，防止重复产出。

## 质量要点（实战教训）

- **小上下文扇出优于全仓投喂**：每个角色只喂脉络+聚焦范围+攻击清单，禁止把整个仓库上下文塞给单角色。
- **每批 5-8 个角色并行**，每角色输出 ≤70 行、假设 ≤18 条；批内角色按"聚焦文件/维度"切分，互不重叠。
- **攻击点从三类来源取材**：台账的契约条目（每条契约都是一个攻击面）、已知问题史（每个已修 bug 的复发面）、扩展视角池的特征缺陷形态。
- **收敛轮与攻击轮的通过语义相反**：攻击轮"零发现"意味着覆盖不足嫌疑（换视角重试）；收敛复核轮"零发现"是成功结果（计入干净轮）。派发词里必须写清本轮是哪种。
- **验证批的配比**：攻击批收口后派独立验证批（每批 ≤12 条假设、验证者与攻击者不同角色档位）；攻击角色自验证无效。
- **跨角色交叉印证要标注**：同一问题被 ≥2 个独立角色命中是高置信信号，验证批优先复核这类；单角色独有假设按常规验证。
