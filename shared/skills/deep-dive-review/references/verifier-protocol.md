# 验证协议（证伪导向）

验证者的任务是推翻问题报告，证伪失败才确认。只问"是不是真的"会让模型顺着假设点头，产出听起来合理的假确认。

## 验证者指令模板（派发时原样带上）

```text
你的任务是证明下面这条问题报告不成立，而不是确认它。

- 报告：{假设内容、触发条件、疑似后果}
- 范围：{文件/目录}
- 先独立读代码取证，再对照报告逐条核查。

输出四态之一：
- confirmed 确认：给出 file:line 证据链和触发路径复述，说明为什么成立。
- refuted 证伪：给出证明它不成立的代码证据。
- undetermined 待定：说明缺什么信息、为什么无法判定。
- duplicate 重复：指出现有台账中的同源条目编号。

禁止：不读代码就下结论；用"可能""大概率"替代证据；自行推断项目是否接受该行为。
```

确认项同时登记影响等级（高/中/低，按触发频率、影响面、自愈能力评估）与交叉印证标注（≥2 个独立攻击角色命中的优先复核）。

## 测试钉住优先

假设可写成确定性测试时（mock 外部依赖，符合目标项目测试纪律），按分工执行：验证者（只读）先定义测试契约——测什么、怎么构造触发条件、什么结果算过/挂；写码档角色实现并运行；独立验证者核对测试是否精确覆盖假设，再归属结果：

- 测试失败，且失败点即假设声称的契约违反 → confirmed（测试随台账保存为复现证据）。
- 测试失败，但失败原因是环境、setup 或与假设无关的原因 → undetermined，不得记 confirmed。
- 测试通过，且触发条件与后果均被精确覆盖 → refuted。
- 测试通过，但未覆盖假设的关键触发条件（如时序）→ 只排除已覆盖场景，假设保持待定。

## 争议升级

同一假设两轮结论不一致，或验证者自评低置信时，升级终审档角色独立裁决，输出同四态。仍无法判定 = undetermined，并区分去向：缺环境、缺证据属**待补证**——继续取证或登记遗留，不得推给用户；技术事实已明确、剩下的是项目取舍，才转 C 类裁决清单。

## 确认项六类分类学

确认（confirmed）后必须归类，六类的处置路径不同：

| 类 | 定义 | 处置 |
| --- | --- | --- |
| 缺陷 | 行为违反项目契约/文档/正确性 | 走 A/B/C 判定进修复流 |
| 回归 | 修复批次自身引入的错误 | 最高优先级即修（A），不等过目 |
| 文档失同步 | 代码正确、文档落后或互相矛盾 | 即修文档（A），先裁决哪边正确 |
| 测试缺口 | 修复/行为缺少能钉住它的测试 | 登记缺口清单；随修复批补齐 |
| 取舍 | 行为是登记过的有意设计 | 台账登记"已裁决接受"+出处 |
| 功能缺口 | 从未存在过的能力，非缺陷 | C 类裁决清单，不计入收敛计数 |

## A/B/C 行为影响判定（缺陷类专用）

判据基准是**项目契约/文档承诺的语义**，不是当前有缺陷的实现。项目缺少契约文档时，以"合法用户在合法输入下能否感知变化"为主判据——无感知即 A、可感知即 B，不得因无文档而把全部修复推成 B 停等批复：

- **A 类·自主修复**：修复后行为与契约/文档一致，或对合法用户在合法输入下完全无感知。含内部正确性修复、防御收紧（只影响非法/恶意请求）、回归修复、文档/测试/注释、结果等价的性能修复。
- **B 类·过目后修**：合法用户可观察的行为变化且无契约依据——新增校验挡住以前成功的请求、成功响应形状/语义变化、缓存与可见性语义、数据保留策略、评分/算法输入语义。
- **C 类·裁决清单**：功能缺口、产品取舍、容量决策、破坏性形状统一。

边界校准（实战案例形态）：把"瞬态错误置终态"改回"瞬态错误自愈"是 A（契约已承诺自愈语义）；把"非法输入 500"改成 400 是 A（防御收紧）；把"评论计数立即可见"改成"TTL 内旧值"是 B（可见性语义变化，无契约依据）；"缺少会话撤销端点"是 C（功能缺口，不是任何被审代码的缺陷）。拿不准时按 B 保守处理。

## 修复流交接

- A 类：即修即登记，验证证据进台账，不计入收敛计数。
- B 类：本轮收口呈报用户，批后执行；出现 B 类确认的轮次不计入连续干净轮。
- C 类：台账裁决清单积累，收口时一次性呈报；永不阻塞收敛。
- 回归类：最高优先级即修 + 当轮落点复核必须覆盖其修复。
