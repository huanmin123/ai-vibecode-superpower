# 深挖复审

把"单轮 review 只见表象"升级为按约定覆盖矩阵迭代、可核验收敛的深挖环。四个核心机制：

- **生成与验证分离**：攻击角色只产出假设（宁滥勿缺），验证角色只做证伪，不自我设限。
- **覆盖矩阵**：扫描范围展开成显式矩阵，"无问题"必须写成"已查 + 理由"的正面结论。
- **证伪导向**：验证者的任务是推翻问题报告，证伪失败才确认。
- **证据链扩散**：修复后沿耦合关系扩一跳，直到连续多轮零 B 类确认。

满足终止判据证明的是审查过程完成了约定覆盖，不证明对象不存在隐藏缺陷。

## 交互与授权模型（核心）

**默认 report-only**：用户显式发起深挖复审即可开始，产出台账、问题记录与终报；A/B/C 只作为建议分级。除约定的审查产物外，不修改目标项目文件，包括源码、配置、项目测试和文档；复现也不得写入这些对象。只有用户显式确认"可以修复"并接受 A 类即修语义后，才进入 fix 模式；授权模式记入台账。

**fix 模式**：一次授权包含三级修复语义；循环自主迭代，B 类须过目：

- **A 类·自主修复**：修复后行为与目标项目契约/文档承诺一致，或对合法用户在合法输入下完全无感知。含：内部正确性（崩溃、竞态、泄漏、悬挂、资源回收）、防御收紧（只影响非法/恶意请求的响应修正，如 500→400、注入拦截、钳制、转义）、修复自身回归、文档失同步、测试与注释、结果等价的性能修复。即修即登记台账，零交互，不计入收敛计数。
- **B 类·过目后修**：合法用户可观察的行为变化且无契约依据——新增校验挡住以前成功的请求、成功响应形状/语义变化、缓存与可见性语义、数据保留策略、评分/算法输入语义。每轮收口随轮报呈报，批后继续；计入收敛计数。
- **C 类·裁决清单**：功能缺口、产品取舍、容量决策、破坏性形状统一——不是缺陷，不进修复流、不计入收敛计数；台账积累，收口时一次性呈报。

判据以契约为基准，不以当前有缺陷的实现为基准：把行为拉回契约已承诺的语义属 A 类（回归修复），无契约依据的新语义/新约束才属 B 类。

report-only 不执行下面的修复与落点复核步骤；收敛判据见第 6 步。

## 边界

| 任务形态 | 走向 |
| --- | --- |
| 复杂开发的过程闭环（边做边审） | orchestrate-model-workflow |
| 交付后/上线前对锚定对象做穷尽深挖 | 本 skill |
| 单点 bug、边界清晰的明确改动 | 直接完成，不进深挖环 |

## 准入前提（缺一不开工）

1. 用户显式发起即采用 report-only；只有用户明确同意 A 类即修权才进入 fix 模式。B 类过目门与 C 类清单语义在发起时向用户说明。
2. 锚定对象明确：一个需求、一个模块或一个变更集，范围写成一句话写入台账。
3. 目标项目可读，其裁决/规范文档（AGENTS.md、docs/ 等）已定位。

## 流程

**0 建档**。按 [ledger-template.md](references/ledger-template.md) 建活台账；报告、台账与问题记录按用户指定位置保存。未指定且项目可写时，台账放目标项目文档惯例位置，无惯例时新建 `docs/plans/deep-dive-review-<对象>-<日期>.md`；项目只读时，使用已授权的项目外位置或会话正文；指定不落盘时只用会话正文。正文交付须注明不能作为持久台账支持跨会话续跑。登记需求脉络（目标、非目标、可见行为、涉及文件、关联契约、项目既有裁决及出处）、代码基线与授权范围（含授权模式：report-only / fix）、问题记录位置。并行会话共用的仓库先核工作区边界：列出既有脏文件、确认迁移/编号等共享序号未被占用、共享文件（索引、CHANGELOG）只追加不重写。台账是唯一状态载体；跨会话续跑先核对基线，同次审核轮间也须核查外部变更：已覆盖内容受影响时，对应覆盖格与证据失效、须重核，干净轮计数清零重算；已登记的本审查正常修复按第 5、6 步的落点复核与回归规则处理，不因此自动清零。

**1 假设穷举（攻击轮）**。按 [attack-matrix.md](references/attack-matrix.md) 选定本轮视角展开覆盖矩阵，按 [attacker-brief.md](references/attacker-brief.md) 的骨架派多个取证角色并行，每个只喂"台账脉络 + 聚焦范围 + 分到的攻击点清单"，产出编号假设：触发条件、疑似后果、初判依据。不要求证据完备，禁止自我审查。登记本轮视角。

**2 对抗确认**。按 [verifier-protocol.md](references/verifier-protocol.md) 派独立验证角色逐条证伪；可写成确定性测试的假设优先测试钉住，report-only 遵守只读边界；争议升级终审档角色。确认项按六类归类，其中缺陷与回归类做 A/B/C 行为影响判定。

**3 裁决对齐**。确认条目对照项目文档：属 C 类的进裁决清单；属 B 类的列入本轮过目清单；A 类在 fix 模式直接进入修复，在 report-only 模式只登记为"建议即修"。找不到契约依据的按 B 保守处理，不自行推断项目意图。

**4 修复（仅 fix 模式）**。A 类即修即登记；B 类清单呈报用户批后执行——呈报与等待批复不阻塞 A 类修复及其落点复核的推进。修复批次纪律：单批不超过 15 条；每条修复必须指明钉住方式（测试 / 复核轮核点）；行为变更守目标项目文档纪律；回归是最高优先级即修项，不等过目。report-only 模式跳过本步：A/B/C 只进终报建议清单。

**5 落点复核 + 重扫扩散（fix 模式）**。修复批次收口后按 [review-round.md](references/review-round.md) 做一轮落点复核（修复正确性 + 修复间交互 + 回归攻击）；随后覆盖矩阵重扫本轮范围（含刚修复的代码——修复本身是新风险源），沿耦合链扩一跳（共享可变状态 > 共享文件 > 事件/调用依赖 > 主题相似），新纳入对象登记进台账扩散记录后同样走 1-4。report-only 模式只做覆盖重扫与扩散，不做修复落点复核。

**6 终止**。三种出口分开记：① **收敛终止**——两种模式在收敛判定前均须至少执行一轮终态复核（见 [review-round.md](references/review-round.md)）；覆盖矩阵全格有带依据的已查结论或有理由的 n/a（大对象可用等价文字结论），连续三轮视角互不相同。待定或未核验的编号不能充当格结论；可明确排除并披露，必需覆盖缺口达到预算时按未完成报告。fix 模式还要求连续 3 轮零 B 类确认、零回归，且无未处置的 B 类待修项；回归确认即重置连续干净轮计数，修复后重新累计，每个修复批须完成落点复核。report-only 模式要求连续 3 轮无新确认项，任何新确认均重置计数，不适用 B 类/回归计数。存在 C 类裁决清单时仍可收口，终报单列移交。② **用户裁决提前收口**——确认烈度持续走低且剩余项性质转为功能补齐/设计取舍时，用户可裁决终止；终报须如实说明收敛协议未走满。③ **中止**——用户叫停、B 类批复未到且已无法继续并达到明确中止条件，或达到最大轮次/时间预算，属未完成，终报列明已覆盖与遗留，不得声称收敛；尚未答复本身不等于拒绝或中止。

## 纪律

- 子代理上下文只含台账脉络、聚焦范围和攻击清单；禁止投喂全仓。
- 角色按职责槽位选：攻击=只读取证档、验证=只读审核档、争议=只读终审档、修复=写码档。独立验证或复核须由未参与同项假设生成或写入的全新实例执行，可串行使用同一角色，不因此抬高权限。预设没有对应槽位时按"同职责最低成本"就近兼任并记录；没有多实例能力时单实例顺序执行，记录"独立生成/验证缺失"，不得把自查称为独立确认或声称完成多角色证伪；用户要求独立验收时标明该要求未满足。
- 攻击假设必须带 file:line + 该行原文片段或符号名；行号对不上时验证者以实际代码为准并纠正。标 guess 的条目必须写明缺什么证据，验证批次优先处理非 guess 条目。
- 台账每阶段更新；每轮收口压缩本轮记录（统计 + 指向问题记录），已证伪条目保留不删。
- 未指定位置时，问题记录与台账同目录，命名为 `deep-dive-review-<对象>-<日期>-issues.md`；由台账引用具体位置，正文交付时明确对应章节，不得只写"详见问题记录"。
- 本 skill 产出的问题台账与终报是过程记录，不代替目标项目自身的测试与验收门禁。
