# 深挖复审

把"单轮 review 只见表象"升级为按约定覆盖矩阵迭代、可核验收敛的深挖环。四个核心机制：

- **生成与验证分离**：攻击角色只产出假设（宁滥勿缺），验证角色只做证伪，不自我设限。
- **覆盖矩阵**：扫描范围展开成显式矩阵，"无问题"必须写成"已查 + 理由"的正面结论。
- **证伪导向**：验证者的任务是推翻问题报告，证伪失败才确认。
- **证据链扩散**：修复后沿耦合关系扩一跳，直到连续多轮零 B 类确认。

满足终止判据证明的是审查过程完成了约定覆盖，不证明对象不存在隐藏缺陷。

## 交互与授权模型（核心）

发起即一次授权，包含三级修复语义；循环自主迭代，只在 B 类出现时停：

- **A 类·自主修复**：修复后行为与目标项目契约/文档承诺一致，或对合法用户在合法输入下完全无感知。含：内部正确性（崩溃、竞态、泄漏、悬挂、资源回收）、防御收紧（只影响非法/恶意请求的响应修正，如 500→400、注入拦截、钳制、转义）、修复自身回归、文档失同步、测试与注释、结果等价的性能修复。即修即登记台账，零交互，不计入收敛计数。
- **B 类·过目后修**：合法用户可观察的行为变化且无契约依据——新增校验挡住以前成功的请求、成功响应形状/语义变化、缓存与可见性语义、数据保留策略、评分/算法输入语义。每轮收口随轮报呈报，批后继续；计入收敛计数。
- **C 类·裁决清单**：功能缺口、产品取舍、容量决策、破坏性形状统一——不是缺陷，不进修复流、不计入收敛计数；台账积累，收口时一次性呈报。

判据以契约为基准，不以当前有缺陷的实现为基准：把行为拉回契约已承诺的语义属 A 类（回归修复），无契约依据的新语义/新约束才属 B 类。

## 边界

| 任务形态 | 走向 |
| --- | --- |
| 复杂开发的过程闭环（边做边审） | orchestrate-model-workflow |
| 交付后/上线前对锚定对象做穷尽深挖 | 本 skill |
| 单点 bug、边界清晰的明确改动 | 直接完成，不进深挖环 |

## 准入前提（缺一不开工）

1. 用户显式发起或授权——授权即含上述 A 类即修权；B 类过目门与 C 类清单语义在发起时向用户说明。
2. 锚定对象明确：一个需求、一个模块或一个变更集，范围写成一句话写入台账。
3. 目标项目可读，其裁决/规范文档（AGENTS.md、docs/ 等）已定位。

## 流程

**0 建档**。按 [ledger-template.md](references/ledger-template.md) 建活台账，放目标项目文档惯例位置；无惯例时新建 `docs/plans/deep-dive-review-<对象>-<日期>.md`。登记需求脉络（目标、非目标、可见行为、涉及文件、关联契约、项目既有裁决及出处）、代码基线与授权范围。并行会话共用的仓库先核工作区边界：列出既有脏文件、确认迁移/编号等共享序号未被占用、共享文件（索引、CHANGELOG）只追加不重写。台账是唯一状态载体；跨会话续跑先核对基线，锚定范围内代码已变则受影响覆盖格与证据失效、干净轮计数清零重算。

**1 假设穷举（攻击轮）**。按 [attack-matrix.md](references/attack-matrix.md) 选定本轮视角展开覆盖矩阵，按 [attacker-brief.md](references/attacker-brief.md) 的骨架派多个取证角色并行，每个只喂"台账脉络 + 聚焦范围 + 分到的攻击点清单"，产出编号假设：触发条件、疑似后果、初判依据。不要求证据完备，禁止自我审查。登记本轮视角。

**2 对抗确认**。按 [verifier-protocol.md](references/verifier-protocol.md) 派独立验证角色逐条证伪；可写成确定性测试的假设优先测试钉住；争议升级终审档角色。确认项按六类归类，其中缺陷与回归类做 A/B/C 行为影响判定。

**3 裁决对齐**。确认条目对照项目文档：属 C 类的进裁决清单；属 B 类的列入本轮过目清单；A 类直接进入修复。找不到契约依据的按 B 保守处理，不自行推断项目意图。

**4 修复**。A 类即修即登记；B 类清单呈报用户批后执行——呈报与等待批复不阻塞 A 类修复及其落点复核的推进。修复批次纪律：单批不超过 15 条；每条修复必须指明钉住方式（测试 / 复核轮核点）；行为变更守目标项目文档纪律；回归是最高优先级即修项，不等过目。

**5 落点复核 + 重扫扩散**。修复批次收口后按 [review-round.md](references/review-round.md) 做一轮落点复核（修复正确性 + 修复间交互 + 回归攻击）；随后覆盖矩阵重扫本轮范围（含刚修复的代码——修复本身是新风险源），沿耦合链扩一跳（共享可变状态 > 共享文件 > 事件/调用依赖 > 主题相似），新纳入对象登记进台账扩散记录后同样走 1-4。

**6 终止**。三种出口分开记：① **收敛终止**——收敛判定前至少执行一轮终态复核（见 [review-round.md](references/review-round.md)），且连续 3 轮同时满足：零 B 类确认、零回归（A 类即修不计入）；覆盖矩阵全格有"已查 + 理由"（或大对象的等价文字结论）；三轮视角互不相同；且无未处置的 B 类待修项。存在 C 类裁决清单时仍可收口，终报单列移交。② **用户裁决提前收口**——确认烈度持续走低且剩余项性质转为功能补齐/设计取舍时，用户可裁决终止；终报须如实说明收敛协议未走满。③ **中止**——用户叫停，属未完成，终报列明已覆盖与遗留。

## 纪律

- 子代理上下文只含台账脉络、聚焦范围和攻击清单；禁止投喂全仓。
- 角色按职责槽位选（档位来自安装预设）：攻击=取证档、验证=审核档、争议=终审档、修复=写码档；预设档位不足时由相邻档位兼任并在台账记录。
- 台账每阶段落盘；每轮收口压缩本轮记录（统计 + 指向问题记录文档），已证伪条目保留不删。
- 本 skill 产出的问题台账与终报是过程记录，不代替目标项目自身的测试与验收门禁。
