# 待办与阻塞事项

> 使用说明（复制后删除本段）：复制本文件到目标项目 `docs/待办与阻塞事项.md`，替换 `<...>` 占位符，删除未使用的示例条目；没有条目的分区保留标题与一行定义。事项完成后立即删除对应条目，不保留“已完成”段落，需要保留的过程与证据写入对应计划、问题或重构档案。

> 定位：多会话共享的当前工作清单，只记录尚未关闭的阻塞、待确认、已明确待排期事项，以及暂不处理但需要观察的事项和其它跟踪载体的指针。

## 使用规则

1. 本文只记录未完成事项。事项完成后立即删除对应条目，不保留“已完成”段落或历史记录；需要保留过程时，写入对应计划、问题或重构档案，并在删除前留下链接。删除条目的提交同时包含完成该条目的改动，git 历史即已完成记录。
2. 新增事项必须放入正确的状态分区，并至少包含：现象或目标、证据、归属、下一步、完成判定和关联。没有可核对证据的事项不进入本清单。
3. 事项使用稳定编号：`B`=阻塞、`C`=待确认、`T`=待办、`W`=观察、`P`=指针，编号为分区字母加递增序号（如 `B1`）。条目标题上方保留 `<a id="<小写编号>"></a>` 锚点，跨条目引用写成 `[#B1](#b1)`。编号一经分配不因状态变化改变，也不因条目删除复用。引用外部计划、设计或提交时提供仓库相对链接或提交哈希。
4. “完成判定”必须是可观察、可验证的结果。证据变化时更新条目；状态变化时移动到对应分区并保留原编号。`W` 观察项升级为问题档案后删除本条并留下档案链接；`P` 指针在对应载体了结后删除。每条 `W` 观察项写明最长观察期，到期强制复核：升级为对应分区或问题档案，或删除本条，不留无限期观察项。

## 条目格式

新增条目按以下顺序组织，内容不适用时写“无”：

```markdown
### <编号> <标题>

- 现象 / 目标：
- 证据：
- 归属：
- 下一步：
- 完成判定：
- 关联：
```
