# 决策记录

> 使用说明（复制后删除本段）：复制本文件到目标项目 `docs/decisions/README.md`，替换 `<...>` 占位符，删除未使用的示例行；没有条目时保留标题、定位、使用规则和空索引表。每条决策单独建档，新增或改变状态时同次更新本索引。
>
> 定位：保存会约束后续工作的方向判断与取舍历史，解释"为什么这样定、当时放弃了什么、什么条件下重审"。本目录不是当前契约：当前行为以 `functions/`、`architecture/` 为准；本次执行记录在 `plans/`；有触发条件的未做事项在 `reserves/`。

## 使用规则

1. 只记录会约束未来工作、且理由不能由当前契约完整表达的判断（下称"符合记录边界"）；局部实现细节、命名格式偏好和普通 bug 修复不进入本目录。
2. 一条决策一个文件，命名 `D-<三位序号>-<短标题>.md`；编号创建后不复用。项目已有分段台账惯例时可用分段文件，但本索引仍是唯一入口，每条保留稳定 ID 和锚点；分段台账的索引链接写成 `[D-001](<台账文件>.md#d-001)`，条目标题前保留 `<a id="d-001"></a>`。
3. 正式状态只用：`已接受`（方向成立，未必已实施）、`已实施`（已落地并与当前契约一致）、`已被 D-xxx 取代`、`已废弃`。`草稿` 只用于尚未确认的提议，不能作为冲突检查依据；放弃的草稿标记 `已废弃`，条目和索引行保留，编号不复用。部分推翻时整条状态保持 `已接受`/`已实施`，在索引状态列或标题注明 `第 N 项由 D-xxx 取代`。
4. 决策记录写背景、备选、决定、理由、后果和影响，不复制契约正文。产生或改变稳定契约时，在条目「影响」中登记 spec 路径，并在 spec 中链接决策 ID。
5. 任何条目（含草稿）不删除；被取代或废弃的条目保留正文，只改状态并写清原因；不得原地改写实质结论或用新计划覆盖历史。
6. 新增、取代、废弃或复核后，同一次交付更新本索引和互链；索引与实际条目不一致视为缺陷。

## 冲突检查

改动架构边界、稳定契约、权限/存储策略、产品范围或明确排除项前执行：

1. 按本次改动的模块、契约和技术关键词筛选上表；只读命中条目，不加载全部决策。
2. 只对 `已接受`/`已实施` 条目判定冲突；`草稿`、`已被 D-xxx 取代`、`已废弃` 只作历史，不作为当前依据；重新引入其方向时可引用历史理由作提示，但不构成冲突门禁。`已接受` 未必已实施，当前契约未体现它是正常的；`已实施` 才核对当前契约是否仍一致，已实施后偏离的以当前契约为准，不得回滚已生效行为，同次补记分叉。
3. 用户当前明确指令优先：决策记录只用于提醒和留痕，不构成否决权。冲突时先呈现原决策和理由；高影响操作仍按项目既有授权门槛核对目标、范围和副作用。
4. 无冲突：按既有决策实施；计划引用决策 ID，不重复写理由。
5. 有冲突且当前指令已覆盖目标、范围和副作用：按指令执行，并在同一交付中记录取代，不再二次确认。
6. 有冲突且指令含糊、目标/范围/副作用未覆盖或授权不清：在写入前停止，向用户呈现冲突条目的编号、日期、原决定、核心理由、当时放弃的方案，以及新要求会改变什么。
7. 用户确认保留原决策：调整本次要求，不改决策记录。
8. 用户确认取代：新增 `D-xxx`，写清改变原因和旧理由为何不再成立；整条被推翻时旧条目标记 `已被 D-xxx 取代` 并互链，部分推翻按条目「取代关系」逐项标注；同次更新本索引和受影响契约。

## 维护规则

- 复核条件命中、外部约束变化或旧理由已不成立时，主动提出重审；未命中时允许长期休眠。复核后维持的，在条目「变更记录」写复核日期、证据和新的复核条件，索引状态不变。
- 定期检查索引与条目一致、取代互链有效、受影响契约和储备引用仍有效，以及已实施决策与当前契约是否仍一致；偏离时按冲突检查的前置判定处理。失效决策标记 `已废弃`，不删除。
- 只补录仍约束未来工作、且理由不能由当前契约完整表达的历史判断，不批量回填所有旧选择。
