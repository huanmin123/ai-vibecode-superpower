# 发布材料模板

> 按项目发布机制保存当次材料；候选位置为 `.local/project-resources/prod/releases/YYYY-MM-DD_NNN/`。发布目录先确认未占用并排他创建，不覆盖旧产物。以下是发布说明、恢复方案与产物校验的最低内容；命令和输出必须脱敏，计划步骤不能写成已执行事实。

## release.md

```markdown
# 发布 YYYY-MM-DD_NNN

- 构建：<时间> / <commit> / <构建人>
- 变更摘要：<关联 PLAN/BUG 与主要变更>
- 产物：<文件名及用途>
- 产物校验：<算法、相对路径、校验结果与证据>
- 部署方式：<脚本入口或命令>
- 部署状态与实际版本：<待部署 / 已验证 / 失败 / 已回滚 / 待核实；引用部署记录>
- 验证摘要：<smoke 结果、健康检查>
```

## rollback.md

```markdown
# 回滚 YYYY-MM-DD_NNN -> <目标版本>

- 触发条件：<什么情况下执行回滚>
- 授权范围：<已有授权是否覆盖目标与副作用；不足时先确认>
- 可恢复前提：<目标产物、配置、备份与恢复验证依据>
- 数据影响：<目标版本与当前 schema/数据是否兼容、恢复是否丢失新数据；不具备恢复条件则停止，不能只切换旧二进制>
- 步骤：<脱敏命令序列>
- 失败停止条件：<在哪一步停止、已发生副作用如何记录>
- 回滚后验证：<smoke 检查项>
- 执行记录：<时间、实际动作、结果、实际版本与指针；未执行写“未执行”>
```

## checksums.txt

采用 SHA-256；生成和验证命令写在项目构建/操作指南中，依据实际平台与已安装工具选用，不能假设 Windows 有 `sha256sum`。文件内每行只有 `<64 位十六进制哈希值>  <产物相对路径>`，不含算法名；校验全部列出产物的字节内容，缺失或不匹配即停止发布。使用同一发布目录为路径基准，不写机器专属绝对路径：

```text
<哈希值>  <产物文件名>
<哈希值>  <产物文件名>
```

## current-release.txt 或等价版本指针

指针记录实际已核实的版本，不由材料生成动作更新。部署切换并通过必需检查后标记成功；切换前失败保持原值。切换后失败或回滚须核对实际生效版本，按项目定义的指针语义同步状态与日志；无法核实则记录“待核实”，不得虚写成功版本。
