# 文档清理与生命周期手册

## 目的与范围

本文定义项目文档的状态、保留、归档、合并、废弃和删除规则。它适用于 `docs/` 下的公开文档、记录、模板和索引，也适用于与文档建立链接或基线关系的 `.local/` 私有层资源；其中 `.local/tmp/` 是任务暂存区，约定只放可再生产物，不进入生命周期管理，可随时清空。仓库根 `external/` 的对外资料不在内部生命周期管理范围内，只受本文删除保护规则的约束，由维护者手工管理。本文不授予删除生产数据、凭据、发布产物或外部系统记录的权限；这些对象仍受项目和平台的授权、保留与恢复规则约束。

清理的目标是消除重复、断链和失效入口，同时保留仍能解释当前行为、历史决策、验证结果和需求基线的证据。清理不应通过删除历史来掩盖失败、未验证项或兼容义务。

## 生命周期

| 状态 | 含义 | 默认处理 |
| --- | --- | --- |
| 草稿 | 尚未评审或尚未生效的候选内容，不能作为当前契约或完成依据 | 可继续完善；确认不再采用时可删除，但须先确认没有入链、基线或外部引用 |
| 生效 | 当前权威来源，维护者和 AI 应按本文执行 | 不得直接删除；行为变化先更新本文并保留变更记录 |
| 已废弃 | 不再用于新工作，但仍可能被外部链接、旧版本或迁移过程引用 | 保留替代文档、废弃原因、生效日期和移除条件；达到条件后再归档或删除 |
| 已归档 | 历史证据或过程记录，不再承担当前规范入口 | 只读保留，文件内标注状态、替代入口和归档原因；入链可指向归档位置 |
| 已删除 | 已从仓库移除，且不再需要作为当前或历史依据 | 仅在清理前证据、恢复物和入链迁移完成后执行；删除记录保留原路径、原因和日期 |

`functions/` 的生效契约和稳定验收条件默认长期保留；`plans/`、`bug/`、`refactors/`、`reports/`、部署记录和发布材料只要承载真实过程或证据，默认归档而不是删除。`docs/待办与阻塞事项.md` 是在用清单，关闭条目可以从清单移除，但需要长期保存的内容必须先建立对应档案并保留链接。`docs/储备与触发事项.md` 同属在用清单，已转正或放弃的储备条目可以移除；转正条目的方案细节随新载体保留，放弃理由随删除提交记录，储备方案本身不构成需要归档的契约。`docs/reserves/` 中、被在用储备条目引用的草稿不是"未引用草稿"，条目存续期间不得据此删除。`external/` 的对外资料由维护者手工管理，不适用内部"未引用草稿可删"规则；废弃或替换前须确认外部已分发副本的影响。状态名称可以按项目语言调整，但不能省略“当前权威”“历史保留”和“已移除”的区别。

## 可清理与不可删除

### 可以删除的对象

- 未被引用、未进入需求基线或发布材料的废弃草稿。
- 已完成合并、且所有入链、索引和外部入口都已迁移的重复文档。
- 目录索引中已确认不存在对应文件的失效占位项，删除前应修复索引而不是留下空链接。
- 按清单规则已关闭的待办条目和已转正或放弃的储备条目；若其过程、裁决或证据仍有复用价值，先转存到 `plans/`、`bug/` 或 `refactors/`。
- 已确认不再需要、且符合项目保留策略的临时生成文件；私有运行产物还必须核对 `.gitignore`、保留期限和恢复要求。

### 默认不得删除的对象

- 当前生效的 `functions/`、架构、API、权限、存储、安全或验证契约。
- 已执行并产生证据的 `plans/`、`bug/`、`refactors/`、`reports/`、部署记录和发布材料。
- 仍被现行文档、代码、计划基线、AC/NFR、发布记录或外部公开入口引用的文件。
- 失败、回滚、未验证、阻塞或争议事项的原始记录；应补充状态或归档，不得删除失败历史。
- 被 `储备与触发事项.md` 在用条目引用的 `reserves/` 储备方案草稿；仅在条目转正升级或放弃删除后，才按草稿规则处理。
- `external/` 中面向外部使用者的资料；废弃或替换由维护者确认，并先评估已分发副本的影响。
- `README.md`、目录索引和清理手册本身，除非替代入口已生效并完成索引迁移。
- 凭据、生产数据、审计材料和外部系统记录；本文只规定文档链接与证据管理，不能替代其专门保留和授权流程。

## 归档、合并、废弃和删除判定

| 动作 | 适用条件 | 必须留下的东西 |
| --- | --- | --- |
| 归档 | 内容不再是当前入口，但用于解释历史决策、版本、验证或事故 | 归档状态、原因、日期、替代入口（如有）、原 ID 和可访问路径 |
| 合并 | 多份文档职责重叠，且能确定唯一权威目标 | 合并后的内容、来源文件清单、冲突裁决、入链迁移和原文件的归档或删除记录 |
| 废弃 | 当前内容有替代方案，但仍存在迁移窗口、外部引用或兼容义务 | 替代文档、废弃原因、生效日期、移除条件、负责人和剩余引用 |
| 删除 | 无当前职责、无保留义务、无入链或已完成迁移，且可恢复性已确认 | 原路径、文件 ID/哈希（适用时）、删除原因、批准人、日期、恢复位置和验证结果 |

不能仅因文件更新时间较早、内容较短、目录看起来重复或计划已经“完成”就删除。无法证明历史证据不再需要时，选择归档。

## 清理前证据与恢复性

清理前建立一份计划或清理记录，至少记录：目标路径和生命周期判断、责任人/批准人、清理原因、关联 `functions/`、`plans/`、`bug/`、`refactors/`、`reports/`、AC/NFR 和发布记录、预计影响、停止条件与恢复位置。

涉及移动、合并、归档或删除的清理，默认在 `docs/plans/` 建立一份带 `PLAN-...` ID 的清理计划；完成清理后如有独立审计或验证结果，再从计划链接 `docs/reports/` 报告。仅修正一个已确认失效的索引链接时，可以追加到现有计划或审计记录，但不能只留在聊天记录或提交说明中。

执行前完成以下核对：

1. 用仓库搜索工具查找目标文件的入链、ID、AC/NFR、标题和旧路径，并检查目录 `README.md`、根 `README.md`、代码注释和脚本入口。
2. 检查 `git status`、跟踪状态和当前 diff，确认目标是否有未提交修改；未跟踪文件在删除前先复制到受控备份或纳入可恢复提交。
3. 对需要长期保留的记录建立归档路径，或保存可恢复快照、提交、补丁和必要的哈希；私有资源按其环境保留和脱敏规则处理。
4. 确认删除不会改变仍在生效的需求基线、AC/NFR、兼容义务、发布材料或回滚路径。发现任何未知入链、未决裁决或无法恢复的目标时停止。

恢复物必须能在当前项目权限和工具条件下被定位、读取并恢复到原路径或明确的替代路径。仅声称“Git 以后可能找得到”不足以证明未跟踪文件或外部产物可恢复。

## 执行步骤

1. 建立清理计划，列出目标、范围、非目标、授权、停止条件和验收证据。
2. 逐项盘点生命周期、入链、索引、基线、保留义务和恢复物，先处理未知项。
3. 选择归档、合并、废弃或删除；合并时先确定唯一权威来源，禁止两份文档继续并列维护。
4. 先更新替代文档、目录索引、根入口、关联计划/报告和基线引用，再移动或删除目标文件。
5. 执行链接、索引、文件状态和差异检查；确认没有孤儿链接、重复权威来源或把归档文档误标为当前入口。
6. 追加清理结果、原始错误、未执行项和恢复信息。清理失败或部分完成时保留原状态，不用删除目标来掩盖阻塞。
7. 对影响当前契约、发布或验证口径的清理，更新对应 `functions/`、`plans/`、`reports/` 或 `deploy/` 记录，并由维护者复核后再交付。

## 定期审计清单

按项目维护周期（建议每月或每个主要版本）检查：

- 每个保留目录的 `README.md` 索引与实际文件一致，链接目标存在且使用相对路径。
- 生效文档有明确状态、权威职责、负责人或维护入口；归档/废弃文档有替代入口和移除条件。
- `functions/ -> AC/NFR -> plans/任务 -> 验证 -> 报告/产物` 的链接和基线仍可追溯。
- 已完成计划、问题和重构记录没有被误删；失败、回滚和未验证历史仍可读取。
- `待办与阻塞事项.md` 没有已关闭条目残留，也没有把需要长期保留的证据留在清单之外。
- 重复主题只有一个生效权威来源；其他文件已归档、废弃或明确链接到权威来源。
- 私有资源仍被 `.gitignore` 正确保护，过期产物按保留策略处理，恢复和脱敏要求没有被清理破坏。
- 最近的清理记录包含目标、原因、影响、恢复性、执行结果和复核证据；未解决项进入待办或阻塞清单。

## 示例

### 合并重复的功能契约

发现 `functions/核心功能设计.md` 和 `functions/导入功能.md` 重复描述同一行为时，先确定一个作为唯一权威来源，把差异裁决写入合并记录；更新所有 `README.md`、计划和 AC 链接；旧文件标记为已归档或在恢复物确认后删除。合并后不得继续修改两份文件。

### 归档已完成计划

计划已经完成但包含失败重试、验证命令和实际产物路径时，将其状态保留为“已完成”并移入项目约定的归档位置，更新 `plans/README.md` 索引。不能因为当前开发已结束就删除计划，也不能把实际结果复制成新的需求契约。

### 删除未采用的草稿

一份草稿从未生效、没有入链、没有进入计划基线，也没有承载评审裁决时，记录搜索结果和恢复副本后可以删除；清理后检查目录索引、根入口和 Git diff，确认没有留下指向该草稿的链接。
