# 穷举模式（exhaustive）

用于用户明确要求"不计成本、尽量穷举"、上线前高保证、重大架构变更或高风险系统。目标不是"找遍世界上所有漏洞"，而是**把有限的审计空间铺满，并证明每一格都处理过**。

> 覆盖空间不是抄下面的轴表，而是从目标生成；轴表只是起点。发现表外对象时新增轴或轴值，不要硬塞进现有分类。

## 1 穷举什么

漏洞空间是开放的，无法穷举；可穷举的是审计空间：

```text
覆盖空间 = 入口 × 信任边界 × 判断视角 × 审计层 × 攻击者画像 × 数据资产 × 状态转换
```

每个轴都从目标项目的产物中枚举，不靠想象：

| 轴 | 来源 |
| --- | --- |
| 入口 | 路由、订阅、任务、CLI、Webhook、Server Action、管理面 |
| 信任边界 | 匿名→登录、租户→租户、应用→数据、应用→第三方、CI→生产 |
| 视角 | [lenses.md](lenses.md) 的视角表（至少 13 个，按目标增补） |
| 层 | [layers.md](layers.md) 的 L1–L8，按授权范围 |
| 攻击者画像 | [attacker-mindset.md](attacker-mindset.md)，按目标业务增删 |
| 数据资产 | 凭据、PII、资金、租户数据、审计日志、密钥 |
| 状态转换 | 订单、审批、配额、邀请、试用、退款、权限变更 |

不是所有组合都有意义：无文件入口的"路径穿越"格写 `n/a` 并给理由。**禁止留空**。

轴和取值都是下界。发现表外入口、身份、层或机制时，新增轴值或新轴，不得因为"表里没有"而丢弃；覆盖审计者专门负责找这些轴外对象。

## 2 角色与隔离

| 角色 | 职责 | 禁止 |
| --- | --- | --- |
| 覆盖规划者 | 建矩阵、切分片、定优先级、分配生成者 | 不参与自己分片的验证 |
| 生成者（多个） | 只在自己分片内产出假设；宁多勿少；附路径与前置条件 | 不给最终状态/严重度，不跨片 |
| 合并者 | 去重、归并变体、串攻击路径、保留冲突与来源、做生成 ID 守恒检查 | 不把不同根因合并，不静默丢假设，不把变体写成散文 |
| 验证者 | 逐条证伪，给 confirmed/needs-runtime/lead/clean | 不验证自己生成的假设 |
| 覆盖审计者 | 检查矩阵空格、挑战 n/a、找漏掉的入口/轴、核对生成 ID 守恒 | 不由规划者兼任，不改 finding |
| 主代理 | 集成、裁决冲突、交付 | 不用自述代替独立验证 |

无法并行时降级为单实例顺序执行，但必须在报告中写明"独立验证缺失"，不得声称完成穷举。

## 3 流程

### 3.1 定义范围

记录：用户的风险优先级（如租户隔离、资金、公开 API）、授权层、环境、时间/成本硬上限、报告输出。用户说"不计成本"时，以**覆盖完整**为停止条件，不按固定时间截断；但仍设硬上限，触顶时如实报告未覆盖，不假装完成。

### 3.2 建覆盖矩阵

按第 1 节展开轴，生成单元格。每格至少记录：入口 ID、视角、层、画像、预期证据、状态（初始 `pending`）。同时标记高风险格：

- 未认证可达、跨租户、管理面、资金/配额、文件上传、反序列化、云元数据、CI 密钥、权限变更。
- 高风险格分配两个独立生成者（不同角度），用于交叉覆盖；其余格单生成者。

### 3.3 并行生成

每个生成者只拿：surface map、自己的分片、相关参考文件。不投喂全仓，不告知其他分片的结论。输出假设台账：

```yaml
id: H-<分片>-<序号>
entry: <入口 ID>
lens: <视角>
layer: <层>
attacker: <画像 + 已有能力>
claim: <可能成立的问题>
path: [ { file, line, note } ]
preconditions: <需要什么条件>
evidence_needed: <还缺什么证据>
```

生成阶段允许推测、允许重复、允许低置信；这是为了召回。**不在此阶段定 severity，不写入最终发现。**

### 3.4 合并

合并者是独立角色（或主代理在无并行能力时执行），按以下顺序：

1. 按根因去重：同一缺失控制/同一 sink/同一授权缺口合并为一条主假设，其余作为变体与影响范围。同一控制缺失但修复点或影响对象不同（例如不同接口需要不同授权策略）不得合并；拆成多条，或一条主假设分列影响，不能把不同修复方式塞进一条。
2. 串攻击路径：把假设按"画像 → 目标 → 入口 → 缺失控制 → 影响"串成链；能升级的标注"还差哪一步"。
3. 保留冲突：同一代码得出相反结论时，两条都保留，交给验证者用证据裁决；不得取平均或按数量投票。
4. 保留来源：每条主假设记录来自哪些生成者、哪些分片、哪些证据；合并台账是唯一事实源。
5. 不做定性：合并只改变组织结构，不改变状态；状态由验证产生。
6. 守恒检查：所有生成假设 ID 必须出现在 `merged_from`、`variants` 或 `dropped` 中；差集必须为空，否则不得进入验证。用脚本做集合运算核对，不以合并者自述为准；变体必须记 ID，不写散文；静默丢失是合并失败，不是去重。

守恒检查示例：

```text
生成 ID 总数: 48
merged_from: 44
dropped（有理由）: 4
差集: 0
```

### 3.5 独立验证

按 [review-loop.md](review-loop.md) 的证伪清单逐条执行：

- 验证者必须未参与该条假设的生成；
- 先从"如何推翻"开始，找不到反证才保留；
- 验证者只验证分配给它的主假设；输出 ID 集合必须与输入一致，不得遗漏、不得新增 finding；发现新线索写入 `new_leads`，回到生成/合并，不进入本轮 finding；
- 高风险主假设由第二个验证者复核；
- 冲突假设由更高一档的验证者裁决，记录双方证据。

### 3.6 覆盖审计

由未参与规划与生成的独立实例执行。输入必须包含**所有生成者台账**，不能只看验证后的 finding：

- 核对生成 ID 守恒：每个生成假设 ID 必须被 `merged_from`、`variants` 或 `dropped` 覆盖；差集列为缺口；
- 检查矩阵每个格是否有状态与理由；`n/a` 是否成立；
- 找漏掉的入口：路由表之外的任务、Webhook、管理面、错误路径、多租户分支、文件/导入导出、服务间调用；
- 找漏掉的轴：新部署层、新画像、新数据资产；
- 抽查至少 10% 的 `clean` 结论；高风险格与所有被覆盖审计者标记的格全查；
- 输出缺口清单，回到 3.2 补格；
- 输出守恒核对：生成 ID 总数、已归属数、缺失 ID、静默丢失列表；缺失不为零时不得通过覆盖审计。

覆盖审计不是"再看一遍代码"，而是**检查覆盖本身**。它不修改 finding，只产出缺口。

### 3.7 未知未知轮

覆盖审计者额外回答：

- 目标有哪些机制不在当前轴里（插件、规则引擎、工作流、导入导出、模型/Agent 工具调用、设备/离线同步、第三方回调）？
- 哪些入口不在路由表/任务注册表里（管理脚本、数据修复脚本、一次性任务、调试端点）？
- 哪些身份不在画像表里（供应商、合作伙伴、匿名 API 调用方、设备、外部运营）？
- 如果攻击者完全不按现有视角出牌，最可能从哪里进？
- 哪些"正常业务功能"组合起来会形成新的攻击面？

发现新轴、新值或新格 → 回到 3.2 建格；不得因为"清单没有"而丢弃，也不得把它塞进"其他"而不说明。

### 3.8 收敛与报告

按 [report.md](report.md) 输出，额外附：

- 覆盖空间表（入口 × 视角 × 层 × 画像，含状态与理由）；
- 合并记录（主假设 ← 生成者/分片/变体/冲突）；
- 生成 ID 守恒表（总数、`merged_from`、`dropped`、差集=0）；
- 覆盖审计记录（轮次、缺口、补格结果、生成 ID 守恒核对）；
- 未覆盖与硬上限触顶说明。

## 4 分区策略

推荐的切分优先级：

1. 按**域**切：授权、解释器、数据/文件、身份/密码学、供应链/配置。
2. 域内按**层**切：L1 代码、L2 配置、L3 供应链；有授权再加 L4–L8。
3. 高风险格按**视角**切第二份：例如授权域拆"功能级/对象级/租户"；注入域拆"查询/命令/模板/反序列化"。

域表同样只是下界；目标有表外域（插件、规则引擎、模型/Agent 工具调用、数据管道）时新增分片，不要硬塞进现有五域。

不要按文件切：文件边界与漏洞边界不一致，容易漏跨文件数据流。不要给两个生成者同一提示词：那会产生高度相关的重复假设。

## 5 合并规则

- 合并单位是**根因**，不是措辞；同一控制缺失的不同入口合并，影响范围写全。
- 变体不单独计数，挂在主假设下；报告只统计主假设。
- 冲突不消除：保留双方证据，由验证裁决；无法裁决的写 `lead` 或 `needs-runtime`。
- 合并后重新编号，保留旧 ID 映射，避免验证与报告错位。
- 合并者不得提升状态；`confirmed` 只能来自独立验证。
- 合并必须守恒：生成 ID 总数 = `merged_from` + `variants` + `dropped` 的去重并集；差集非空时不得交付。

## 6 停止条件

同时满足才停：

1. 覆盖矩阵每格有状态：`confirmed` / `needs-runtime` / `lead` / `clean` / `n/a`，`n/a` 有理由。
2. 所有 `confirmed` 完成独立验证；高风险格完成双验证或有明确豁免记录。
3. 未知未知轮完成；连续两轮覆盖审计没有发现新格、没有发现不成立的 `n/a`、没有生成 ID 丢失。
4. 合并台账无未裁决冲突，且生成 ID 守恒差集为零。
5. 验证输出 ID 集合与输入主假设 ID 集合一致：无遗漏、无新增 finding；新线索已单列。
6. 未覆盖项与硬上限触顶项已列明。

达到条件只证明"约定的覆盖空间已铺满"，不证明不存在未枚举的入口或未知攻击类。报告必须保留这句话。

## 7 失败模式

| 失败 | 后果 | 纠正 |
| --- | --- | --- |
| 多个 agent 同提示词 | 重复假设，覆盖率不增 | 按域/层/视角切互斥分片 |
| 生成者兼验证者 | 自我确认，误报与漏报同时升高 | 验证者独立，必要时应换档 |
| 合并按措辞去重 | 同一根因拆成多条，统计虚高 | 按根因与 sink 合并 |
| 覆盖审计由规划者兼任 | 空格被合理化 | 独立实例，专查缺口 |
| 用时间/成本截断冒充完成 | 未覆盖被隐藏 | 触顶写"未完成穷举" |
| `n/a` 无理由 | 覆盖假象 | `n/a` 必须给证据与理由 |
| 只扩入口不扩轴 | 新增部署层/画像被漏 | 每轮同时检查轴 |

## 8 与现有机制的关系

- **`deep-dive-review`**：提供"生成与验证分离、覆盖矩阵、对抗证伪、收敛判定"的方法骨架；本模式把它用于安全轴，并保持只读、只出报告，不沿用其自主修复语义。
- **`orchestrate-model-workflow`**：提供角色选择、并行派发、独立复审与主代理集成；本模式只定义安全专用分片与合并规则。
- **`security-audit` 其他参考**：视角、层、攻击者画像、授权、供应链、报告格式；本模式不重复这些内容。

如果当前环境没有多实例能力，按 3.2–3.8 顺序单实例执行，并在报告中记录"无独立生成/验证/覆盖审计"，不得用"已穷举"表述。
