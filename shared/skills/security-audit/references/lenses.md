# 判断视角

安全问题的形态随语言、框架、版本变化，但成立条件稳定：

> 有人能影响的数据，越过一条信任边界，到达一个会放大它的操作，而该处的控制不覆盖这种语义。

审计用一小组固定视角反复提问，而不是背漏洞清单。视角负责"往哪看"，具体 API、默认值和历史漏洞在审计时按目标版本查证。

**视角表是下界，不是全集。** 目标出现表外的边界、协议、组件或业务机制时，新增视角并纳入台账；不得因为"表里没有"而跳过。下面 13 个视角是起点，不是上限。

## 1 暴露面与可达性

**问**：有哪些入口？每个入口由谁触发、从哪条网络路径到达、经过哪些中间件？

**证据**：路由/订阅/任务注册点、中间件与 guard 链、启动配置、部署清单、网关与反代规则、feature flag。

**成立条件**：存在从外部边界到该处理逻辑的可达路径。

**不能推出**：仓库里有 handler 不等于公网可达；没有部署证据时只能写暴露假设。

**常见形态**：未在 UI 出现的接口、调试/测试端点、内部 API 与管理面共用入口、只在特定环境注册的路由、被注释掉但仍被反射加载的 handler。

**误报**：文档存在但代码未注册；父路由/网关已统一拦截；handler 只在测试中使用。

## 2 授权与所有权

**问**：主体、动作、对象、上下文四个维度是否都校验？校验点在哪一行？

**证据**：入口 → 中间件 → handler → 查询/操作的完整链条；对象级判定；租户谓词；数据库 RLS/策略。

**成立条件**：攻击者能用低于预期的权限，对不属于自己的对象执行动作。

**不能推出**：有 `requireAuth` 不等于有授权；前端隐藏不等于服务端拒绝。

**常见形态**：IDOR/BOLA、列表过滤但详情不过滤、管理接口只做登录校验、租户来自请求体、批量接口只校验第一项、后台任务不重新校验。

**误报**：全局策略/数据库 RLS/网关已强制；序列化层只返回允许字段。

详见 [authz.md](authz.md)。

## 3 解释器边界

**问**：这个值最终进入哪个解释器？它被当作**数据**还是**结构/代码**？

**证据**：source → 每一跳 → sink；绑定/参数化/编码/白名单发生在哪一层、是否覆盖当前语义。

**成立条件**：用户可控内容参与结构或代码的构造，且转义/绑定与目标解释器不匹配。

**不能推出**：出现危险 API 不等于可利用；参数化查询旁边的拼接才是问题。

**常见形态**：

- 查询语言：SQL/NoSQL/HQL/JPQL/Cypher，值拼接与标识符拼接。
- 操作系统：shell 命令、参数注入（`--flag`）、路径查找。
- 代码与表达式：动态求值、表达式语言、动态导入、反序列化。
- 模板与标记：服务端模板、客户端 DOM、邮件模板、日志格式。
- 正则与查询语法：回溯型引擎、LDAP/XPath 过滤器。

**误报**：输入被强类型/枚举约束；使用安全 API 且语义匹配；代码不可达。

## 4 身份、会话与令牌

**问**：身份从哪里来？如何证明？如何携带？如何失效？

**证据**：认证实现、口令存储、重置流程、token 签发与验证参数、会话存储与 cookie 属性、登出与撤销。

**成立条件**：攻击者能冒充、固定、重放、提升或长期持有身份。

**不能推出**：用了成熟库不等于配置正确；JWT 里有 `role` 不等于可以跳过对象级授权。

**常见形态**：弱口令策略与无限尝试、重置 token 可预测/可复用、会话不轮换、登出后 token 仍有效、算法未固定、`kid`/`jku` 可控、把 token 声明当权限事实。

**误报**：身份由受信 IdP 处理且校验完整；token 只用于传输，授权仍查服务端。

## 5 文件、URL 与外部数据

**问**：数据能否让服务读写预期之外的文件、访问预期之外的主机、加载预期之外的对象？

**证据**：路径构造与规范化、基目录约束、归档条目校验、上传存储位置与执行权限、URL 解析与重定向、反序列化类型控制、XML 解析器配置。

**成立条件**：用户可控内容决定资源定位或对象构造，且约束可被解析差异/编码/符号链接/重定向绕过。

**不能推出**：用了 `join`/`basename` 就安全；URL 白名单未在解析后校验仍可绕过。

**常见形态**：路径穿越、Zip Slip、上传 webshell、SSRF（含云元数据）、XXE、反序列化 gadget、开放重定向。

**归档解压**：不能只凭 `extractall`/解压 API 的名字判定 clean。按目标运行时版本与平台核对条目名清理行为（绝对路径、`..`、盘符、尾随空格/点、符号链接），平台未知时写 `needs-runtime`。

**误报**：固定资源映射；解析后 IP 校验；数据格式为纯数据且类型固定。

## 6 状态、并发与业务规则

**问**：检查与使用之间，状态是否可能被并发修改？流程能否跳步或重放？

**证据**：事务边界、锁与唯一约束、幂等键、状态机迁移、限额计算、队列重试语义。

**成立条件**：非原子操作或缺失约束让攻击者获得不应得的次数、金额、状态或优先级。

**不能推出**：有事务不等于隔离级别足够；前端禁用按钮不构成限制。

**常见形态**：余额/库存/优惠券并发、OTP 重放、邀请码复用、审批跳步、重复提交、重试导致重复扣款。

**误报**：数据库唯一约束/行锁兜底；串行队列；网关强制幂等。

## 7 加密、随机与密钥

**问**：算法、模式、随机源、密钥生命周期是否与用途匹配？

**证据**：算法与参数、IV/nonce 生成、随机源、密钥来源与轮换、TLS 校验、口令哈希。

**成立条件**：可预测性、可重放性或密钥暴露足以破坏机密性/完整性。

**不能推出**：用了加密库就安全；哈希存在不等于口令存储正确。

**常见形态**：ECB/固定 IV、nonce 重用、`math.random` 类随机用于安全场景、口令用快速哈希、自签/关闭校验、密钥进仓库或客户端。

**误报**：非安全用途的哈希/随机；仅本地测试关闭校验且不可达生产。

## 8 资源与失败模式

**问**：异常、超时、海量输入或部分失败时，系统是拒绝还是放行？资源是否有界？

**证据**：超时与上限、分页/批量限制、解压比率、正则引擎、错误处理分支、重试与降级。

**成立条件**：攻击者能用低成本输入造成不可用、绕过限制或在失败时获得更高权限。

**不能推出**：有 try/catch 就是安全；错误被吞掉可能意味着 fail-open。

**常见形态**：ReDoS、压缩炸弹、无界上传/查询、连接耗尽、异常路径跳过授权、错误页泄露内部信息。

**误报**：线性正则引擎；网关层限流且覆盖该入口；失败即关闭。

## 9 配置与默认值

**问**：生产实际生效的配置是什么？与仓库默认差在哪？

**证据**：配置文件、环境变量、启动参数、部署覆盖、管理端口、调试开关、安全响应头。

**成立条件**：不安全的默认值在生产生效，或配置可被低权主体修改。

**不能推出**：仓库默认不等于生产配置；改了模板不代表已部署。

**常见形态**：debug、默认口令、开放管理端点、宽 CORS、关闭 CSRF/TLS 校验、详细错误、默认目录列表。

**误报**：生产配置明确覆盖且可核实；端点仅内网且无敏感操作。

## 10 主机、网络与运行环境

**问**：进程以什么身份运行？哪些端口对谁开放？主机与网络边界由谁维护？

**证据**：账户与 sudo、SSH 配置、监听端口、防火墙/安全组、服务单元、文件权限、补丁级别、容器运行时、TLS 终止点。

**成立条件**：运行环境的暴露或权限配置让应用层控制被绕过或放大。

**不能推出**：没有主机访问就不能判断主机状态；不能从仓库推断线上端口与补丁。

**常见形态**：服务以 root 运行、SSH 密码登录/root 直登、管理端口对公网、过度 sudo、敏感文件全局可读、未打补丁、容器特权模式、宿主网络。

**误报**：有堡垒机/网络隔离且可核实；只读挂载且无敏感数据。

详见 [layers.md](layers.md) 与 [server-baseline.md](server-baseline.md)。

## 11 供应链与构建

**问**：依赖、构建脚本、CI 与产物在到达运行环境前，谁能改、改了什么、能否验证？

**证据**：锁文件、安装脚本、构建配置、CI 权限与触发条件、镜像来源与 digest、签名与 provenance。

**成立条件**：不可信代码或凭据进入构建/运行链，且缺少完整性校验。

**不能推出**：依赖有 CVE 不等于本仓库可利用；SBOM 存在不等于产物可信。

**常见形态**：typosquat、安装脚本执行、未固定 Action/镜像、过宽 CI 权限、`pull_request_target`、密钥进日志、无签名发布。

**误报**：开发依赖且不进入产物；版本不受影响；有完整性和权限约束。

详见 [supply-chain.md](supply-chain.md)。

## 12 可观测性与审计

**问**：关键操作是否留痕？日志里有没有秘密？出事能否定位到主体与对象？

**证据**：认证/授权/管理操作日志、日志字段与脱敏、错误响应、审计保留与完整性。

**成立条件**：攻击者能长期操作而不被发现，或日志本身泄露敏感数据。

**不能推出**：有日志不等于可审计；日志分散在不可信主机上不构成证据。

**常见形态**：日志打印 token/口令/PII、CRLF 注入伪造日志、无失败登录记录、无管理操作审计、日志可被应用账户删除。

**误报**：平台侧已统一采集与脱敏；应用日志不含敏感字段。

## 13 原生与内存边界

**问**：长度、索引、生命周期与 FFI 边界是否受控？

**证据**：`unsafe`/native 块、边界检查、整数运算、分配与释放、外部函数接口、编译选项。

**成立条件**：不可信输入影响内存布局或生命周期，且缺少检查。

**不能推出**：安全语言就没有内存问题（native 依赖/FFI 仍可能）；有 `unsafe` 就一定有漏洞。

**常见形态**：越界读写、UAF、整数溢出/截断、双重释放、未初始化内存、FFI 布局不匹配。

**误报**：有明确不变量且输入受控；成熟库封装；启用溢出检查与边界检查。

## 清单之外

每个入口都额外问五个问题，防止"表里没有就跳过"：

1. 这个入口有没有表外的上游/下游（队列、Webhook、插件、脚本、批处理、第三方回调）？
2. 有没有不在画像表里的身份能到达它（供应商、合作伙伴、匿名 API 调用方、设备、外部运营）？
3. 有没有不经过 HTTP 的数据流（导入导出、备份、日志管道、离线同步、模型/工具调用）？
4. 目标有没有本项目独有的机制（规则引擎、工作流、插件、模板、表达式、批处理）？
5. 如果攻击者完全不按这些视角出牌，最可能从哪里进？

答不上来的，写成 `lead` 或 `not-covered`，不要写 `clean`。

## 使用方式

1. 对 surface map 中每个入口，按现有视角顺序过一遍；表外视角按目标新增，并写入台账。
2. 每个视角先找**证据**，再判断成立条件；没有证据的写 lead，不写结论。
3. 视角只提供提问方向；具体 API、默认值、历史漏洞按 [stack-playbook.md](stack-playbook.md) 的方法在目标版本上查证。
4. 报告中的 `class` 使用主视角对应的 CWE；复合问题在正文说明关联视角。
5. 视角表不是覆盖率证明；覆盖率由入口 × 视角的台账承担。
