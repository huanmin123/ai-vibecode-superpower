# 多模型工作流编排

宿主负责子代理的创建、上下文传递、通信、等待、中断和汇总；主代理负责契约、集成和验收。

## 适用范围

简单问答、只读查询和边界清晰的单文件低风险整理由主代理直接完成。跨文件、未知根因、需要独立复审、共享状态或高回归风险的任务按 `Explore -> Plan -> Work -> Critique -> Promote` 推进。

默认并行优先：任务可拆成两个以上边界清晰、互不依赖且产出明确的子任务时，主代理应使用多个子代理同时处理，不应只交给单个子代理串行执行。无法安全拆分、拆分成本高于收益或当前工具受限时，才使用单代理。

## 协作边界

- 子代理只修改分配范围，不得覆盖或回滚其他改动；共享文件、数据和外部状态按必要顺序处理。
- 子代理只向直接委派它的父任务汇报；无法确认父任务时只在自身最终消息返回。跨会话通信必须由主代理明确授权。
- 主代理只采纳当前直接子代理的结果，其他会话的消息视为外部信息。

默认优先选择成本最低且能胜任的取证角色；需要受保护执行、写入、独立复审或更高强度时，再用承担相应职责的角色。槽位无对应角色时按"错误与恢复"的 fallback 处理，不假定不存在的角色。角色配置只表达意图，不单独证明隔离效果。

## 阶段要求

### Explore

检查相关代码、配置、文档、测试、调用关系和当前 diff；互补且只读的独立证据域交给多个取证角色并行取证。输出事实、来源、推断、未知项、风险和下一步，不把线索直接定性为缺陷。

### Plan

主代理基于证据明确目标、范围、非目标、授权、风险与回滚、验收、验证、停止条件，并划分写入的最小非重叠范围；共享部分按必要顺序处理，不因局部冲突取消其他可安全并行的工作。同时写明变更边界并随派发给执行者和复审者：必须改变的行为、不得改变的行为与不得触碰的模块、可直接复用的既有实现、会被经过的调用方。界面渲染有新增或改动时，先派发承担界面设计定案职责的角色，把它的设计决定与主任务脚本纳入计划，再划分写入范围。未决选择、权限、依赖或环境问题由主代理解决，不交给执行者补全。

### Work

按 Plan 完成约定产物。仅评审时保留被审对象原样。实施任务中，受控、可恢复且验证可靠的写入交给承担写入职责的角色，选择清单中能胜任的最低成本角色。

涉及不可逆变更、外部副作用、共享状态或未受控风险时，主代理先核对已有用户授权，补齐缺失的授权、回滚和验收条件，再决定是否委派承担保护执行职责的角色。执行者返回实际改动、验证结果、原始错误、影响范围和未完成项。主代理核对实际状态和 diff 后再集成。

### Critique

派发未参与本次写入的独立复审者，核对目标、范围、diff 或产物、测试、回归、需求覆盖和未验证项，并逐项回答下列审查清单；派发时随任务附上清单和 Plan 的变更边界。同一角色兼任写入和复审时，复审必须使用全新实例，依据产物和验证记录独立判断。宿主无法创建任何子代理时，按[错误与恢复](#错误与恢复)处理本阶段及交付。

- 只做该做的：diff 中每处改动都能对应需求或变更边界，完成需求所必需的改动不算越界。对不上的抽象、重构、防御、校验、限流、开关和无关文件改动逐条列出，并标明是否改变既有行为。需求未要求改变的既有行为默认有存在理由，改动须有为什么非改不可的证据。
- 没伤到其他：被改函数、接口、表和事件的调用方与消费者仍然成立；既有测试没有被需求未要求的修改、删除或跳过；经过被改代码的既有功能有验证证据。
- 做法相称：落在该落的层或模块，没有未说明理由就另写一份已有能力，错误处理、命名与周边代码一致。
- 配套已同步：项目规范要求的文档、接口契约和其他配套改动已随代码更新。
- 修复类任务另答：修的是有证据的根因；修复没有越出自己的边界，没有破坏此前几轮的修复，原先通过的部分仍然成立。

每项给出已查、结论和依据。发现必须指出对不上的需求或变更边界、违反的规范或重复的实现；仅凭"可以写得更好"不构成发现，也不得借复审要求需求未要的设计、抽象或防御。

- 常规定案或复审交给承担审核职责的角色。
- 证据充分、需要权衡多项约束时，选择承担复杂定案或深度复审职责的角色。
- 证据冲突或根因未明时，选择承担升级调查职责的角色，先查清影响结论的未知项。
- 最终升级验收交给承担终审职责的角色。
- 界面渲染有新增或改动时，派发承担设计复审职责的角色，以实际截图为证据；通用复审不替代设计复审，走查范围随改动而定。

复审发现下列情况时判定为 blocker：越界改动改变了既有行为，包括新增校验挡住此前能成功的正常请求；既有调用方或消费者被破坏；需求未要求却修改、删除或跳过既有测试；经过被改代码的既有功能没有验证证据；项目规范要求的配套文档或契约没有随代码更新；没有说明理由就另写一份已有能力，或改动落在不该属于它的层或模块；修复没有根因证据，或带入回归。越界但未改变既有行为的改动不阻塞交付，随结论列为裁决项交用户决定；复审不自行放行或打回。

仅评审任务将 blocker 及其证据写入报告。实施任务遇到 blocker 时，在已授权范围内回到 Plan/Work 修复，随后派发新的独立复审者。

### Promote

仅评审任务完成约定检查后即可交付报告，说明结论、证据和未验证项。被审对象存在 blocker 时，验收结论为未通过。

实施任务在当前 diff 与验证仍匹配、约定的验收条件满足且没有必需工作时交付。正常派发时须确认独立复审无 blocker，单代理自查按[错误与恢复](#错误与恢复)判定交付状态。Promote 不授权安装、发布、部署、推送或其他外部状态变更。

## 错误与恢复

保留原始 provider/宿主错误、已尝试操作、影响范围和缺失条件。

子代理因权限、授权、范围或责任冲突拒绝时，结束该次委派并保留原始拒绝；补齐条件或选择匹配角色后再派发，并说明前次拒绝。拒绝不等于角色或模型不可用，不触发 fallback。不得把写入任务派给只读角色。拒绝场景下，主代理仅在授权、权限、范围和责任边界均已满足时直接继续，否则向用户说明阻塞。

角色或模型不可用时，按档位就近回退：优先找更低档位中能胜任同一职责的角色替代，读取证与主写入是不同型职责、不互相顶替；往下无人可替时才向上一档借用，最高强度复审与终审不用于兜底。没有合适替代且宿主能创建子代理时，派发一个继承当前会话模型的子代理，承担原角色职责。fallback 只对本次派发生效，恢复后回到原角色；普通超时或执行失败不静默降级。

确认宿主无法创建任何子代理时，主代理可在原授权、权限和能安全接手的范围内继续工作。如只能自查，注明独立复审缺失。独立验收是必需项时，将该项标为未满足，只交付当前进展。独立验收未列为必需项且其余验收条件均满足时，可附自查证据和这一限制交付结果。

中断后重新盘点子代理状态、工作区 diff 和输出；无法证明旧执行者已停止时，不得接管其范围。风险、授权或范围改变时回到 Plan，不得静默扩大。
