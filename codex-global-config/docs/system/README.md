## 命令生命周期

多个场景同时命中时，叠加读取要求；例如 Windows 通过 SSH 操作 Linux 时，需要 Windows、SSH 和 Linux 文档。

1. **预检**：确定工作目录、目标路径、解释器或工具来源，以及项目已有脚本、锁文件和工具链。
2. **构造**：路径和动态值保持为独立参数；本地与远端命令各自使用目标 Shell 的语法，不依赖上一条会话状态。
3. **验证**：原生命令检查退出码；写操作还要检查目标状态、产物或健康结果。`rg` 的 `0` 是有匹配，`1` 是无匹配，只有大于 `1` 才是错误。
4. **失败处理**：先保留并判断错误证据，不轮流试多套命令，也不覆盖用户已有修改。需要破坏性、外部或生产操作时遵守全局授权边界。

平台文档负责具体命令、安装方式和平台风险；本文件不重复这些细节。
