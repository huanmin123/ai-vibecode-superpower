| 场景 | 必读文档 | 额外条件 |
| --- | --- | --- |
| Windows 本机 | [Windows 与 PowerShell 7](windows.md) | 优先使用 PowerShell 7 语法和盘符路径 |
| macOS 本机或远端 | [macOS](macos.md) | 按实际架构和工具链执行 |

## 命令生命周期

多个场景同时命中时，按需叠加读取；例如 Windows 通过 SSH 操作 Linux 时，需要 Windows、SSH 和 Linux 文档。只读取会影响当前命令构造、执行或验证的部分。

1. **预检**：确定工作目录、目标路径、解释器或工具来源，以及与当前任务相关的项目脚本、锁文件和工具链。
2. **构造**：路径和动态值保持为独立参数；本地与远端命令各自使用目标 Shell 的语法，不依赖上一条会话状态。
3. **验证**：先检查原生命令退出码，再按风险选择验证深度。普通本地低风险写入通常核对退出码和预期产物；破坏性、外部状态、生产或用户明确要求的写操作，再核对目标状态、产物或健康结果。`rg` 的 `0` 是有匹配，`1` 是无匹配，只有大于 `1` 才是错误。
4. **失败处理**：先保留并判断错误证据，不无证据地轮流尝试多套命令，也不覆盖用户已有修改。若错误证据表明当前命令不适用，可选择一个有依据的替代路径并保留原始错误；不要把只读探测或空结果自动判为失败。需要破坏性、改变外部状态、生产或敏感数据操作时遵守全局授权边界。

平台文档负责具体命令、安装方式和平台风险；本文件不重复这些细节。
